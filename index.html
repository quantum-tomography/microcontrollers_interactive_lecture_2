1. IDE, Debugging & Design Stages

Understanding Integrated Development Environments, in-circuit debuggers, flashing interfaces, and Stage 1 design partitioning.

Integrated Development Environments (IDEs)

An Integrated Development Environment (IDE) is a unified software suite combining source code editors, C/C++ cross-compilers, assemblers, linkers, hardware programmers, and debugging interfaces into a single application.

VS Code + PlatformIO Modern cross-platform environment supporting multiple architectures (ESP32, ARM Cortex-M, AVR) with integrated library management.
STM32CubeIDE STMicroelectronics official Eclipse-based IDE with integrated peripheral graphical initialization (CubeMX).
MPLAB X IDE Microchip's standard IDE for PIC and AVR microcontrollers with hardware register views and MCC code generation.
Keil MDK / uVision Industry-standard commercial ARM Cortex IDE known for high-performance optimization and real-time execution trace.
Software Simulators

Software environments running purely on the host PC that model the CPU core and instruction execution in software without physical hardware connected.

🟢 Pros: No physical hardware required.
🔴 Cons: Cannot accurately simulate complex real-world analog noise, timing jitter, or physical peripheral interactions.

In-Circuit Debuggers (ICD) / Emulators

Dedicated physical hardware pods (e.g., ST-Link, J-Link, PICkit) that bridge the host PC (USB) to dedicated debug silicon inside the physical MCU.

⚙️ Capabilities: Line-by-line stepping, real-time memory/register inspection, hardware breakpoints on live silicon.

Hardware Debug & Programming Interfaces Glossary

SWD (Serial Wire Debug) 2-pin ARM Cortex protocol (SWCLK + SWDIO) replacing bulky JTAG while retaining full debug capability.
JTAG 4/5-pin IEEE standard (TMS, TCK, TDI, TDO) for deep chip verification and multi-device boundary scan.
ICSP / UPDI In-Circuit Serial Programming (Microchip PIC) and Unified Program and Debug Interface (Modern AVR).
CMSIS-DAP Open-source driverless ARM standard for USB debug probes.
ST-Link & Segger J-Link Hardware USB probes providing the physical signal translation between PC IDE commands and target MCU debug lines.

Stage 1 Embedded Design Lifecycle: Hardware / Software Partitioning

The initial architectural phase of an embedded project involves deciding which functions to implement using dedicated physical hardware components versus firmware code running on the microcontroller.

Hardware Implementation Offloads tasks to dedicated ICs or passive circuits. Ultra-fast, deterministic performance, but increases PCB size, BOM cost, and hardware inflexibility.
Software / Firmware Implementation Executes algorithms on the MCU CPU. Reduces hardware component count and enables easy post-launch field updates, but consumes CPU clock cycles.

Fundamentals of Number Systems

A number system defines how numerical quantities are represented. They are divided into two main categories:

Non-Positional Number Systems

Symbols represent static values regardless of position (e.g., Roman Numerals: III = 3, IX = 9). Arithmetic operations with non-positional systems are extremely difficult to implement in hardware.

Positional Number Systems (Base $q$)

The value of each digit depends directly on its position relative to the radix point. Calculated using the weighted summation formula:

N = ∑ (d_i × q^i) = d_n q^n + ... + d_1 q^1 + d_0 q^0 + d_-1 q^-1 ...

Microcontroller Binary Representation & Transistor Physics

Microcontrollers operate exclusively in the Binary System (Base 2) using digits 0 and 1 due to silicon transistor physical characteristics:

Physical Realization

Transistors function reliably as electronic switches with two states: Cutoff (OFF) and Saturation (ON).

Qualitative Reliability

Logic depends on current flow existence, not precise microampere values, rendering circuits immune to noise.

Arithmetic Simplicity

Base 2 drastically simplifies silicon logic gate design for ALU additions, multiplications, and boolean logic.

3. GPIO Interfacing, Pull-Up Resistors & Current Limits

Understanding input logic signal driving, internal/external pull-ups, current sinking vs. sourcing, and overcurrent limits.

1. Driving Input Pins & Pull-Up Resistors

When connecting buttons or external switches to a microcontroller input pin, driving a low logic level ('0') is done by directly shorting the pin to Ground (GND). However, providing a high logic level ('1') requires a pull-up resistor (R = 10 kΩ) connected to VDD.

Why is a Pull-Up Resistor Mandatory?

If you connect VDD directly to an input pin without a resistor, pressing a switch wired to GND would short-circuit VDD directly to GND! The 10 kΩ pull-up limits short-circuit current while pulling the floating pin safely to VDD when the switch is open.

Internal Weak Pull-Ups (OPTION_REG)

Many microcontrollers (such as Microchip PICs) feature built-in programmable pull-up resistors on select ports (e.g., PORT B). These internal pull-ups are enabled by clearing Bit 7 of the OPTION_REG register.

2. MCU Pins as Current Sinks & Sources

When configured as digital outputs, microcontroller I/O pins can actively sink current from an external load or source current to drive devices like LEDs.

a) Current Receiver / Sink (Приемник) Max: 25mA

The load is connected between VDD and the MCU output pin. When the pin output is driven LOW ('0'), the internal transistor grounds the node, pulling current into the chip (U_OUT = 0V).

💡 Maximum allowable sink current per pin: 25mA.

b) Current Source (Източник) Max: 20mA

The load is connected between the MCU output pin and GND. When the pin output is driven HIGH ('1'), the MCU supplies current out of the chip to the load (U_OUT = VDD).

💡 Maximum allowable source current per pin: 20mA.

⚠️ Overcurrent Protection & Thermal Damage

While MCU pins can drive LEDs directly, care must be taken not to exceed current ratings. Exceeding 25mA (sinking) or 20mA (sourcing) will destroy the individual I/O pin drivers or damage the entire I/O port! Always include external current-limiting resistors (R).
